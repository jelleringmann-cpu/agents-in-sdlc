GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、その作業がマシン上でリアルタイムに進むため、ツールの呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または却下できます。また、エディターを離れずに追加のプロンプトを送って、作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューし、承認します。
- セッションの途中でエージェントに指示を追加し、高コントラストに加えてライトモードのトグルも作成します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、高コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザーのために、ライトモードのトグルも追加したいとのことです。新しい会話を最初から始める代わりに、現在のセッションに指示を加えて作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択して変更を承認します。
   - **Undo** を選択して変更を取り消し、エージェントにやり直してもらいます。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したファイルをまとめて確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう依頼する

高コントラスト モードを実装できたので、同じ会話でライトモードのトグルも追加します。同じチャット セッションを続けるため、エージェントはこれまでの作業コンテキスト (変更したコンポーネント、スタイルの方法、設定したローカル ストレージのパターンなど) を保持しています。

1. Copilot Chat の入力欄に、次のプロンプトを送信します。

   ```plaintext
   よくできました。高コントラストのトグルに加えて、ライトモードのトグルも追加してください。ライトモードも同じ方法で実装し、設定をローカル ストレージに保存して、同じ UI 領域から切り替えられるようにしてください。ユーザーが高コントラスト モードとライトモードを個別に有効にできるようにしてください。
   ```

2. エージェントはすでに行った変更を調べ、続けてライトモードを追加します。
3. 高コントラスト モードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが望まない方針 (たとえばトグル UI を好まない方法でリファクタリングするなど) に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止します。その後、明確な指示を追加します。

> [!TIP]
> 作業中のセッションに指示を加える方が、最初からやり直すよりも速く進められます。追加のプロンプトで変更を依頼できます (例: 「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)。また、方向を調整したり (例: 「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを統合してください」)、作業範囲を広げたり (例: 「両方のトグルにキーボード ショートカットも追加してください」) できます。

## 変更されたファイルを確認する

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージでの設定維持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して方向付けしました。ファイル編集を確認しながら、個別の変更を承認または却下し、会話のコンテキストを保ったまま追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を承認または却下する方法
- 追加のプロンプトでセッションの進行中に方向を調整する方法

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが作成した変更をレビューします。
