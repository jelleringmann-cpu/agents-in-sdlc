アプリケーションを少し変更するだけでも、通常は複数のファイルを更新し、テストを実行するなどの作業が必要です。開発者は、関連ファイルを探し、変更を加え、テストを実行し、問題をデバッグし、更新し忘れたファイルを見つけて、さらに変更を加えます。こうした作業は続いていきます。

このような場面で、Copilot エージェントモードが役立ちます。

Copilot エージェントモードは、IDE 内でより自律的に作業できるよう設計されています。開発者と同様に、既存のプロジェクト構造を調べ、必要な更新を行い、テストなどのタスクを実行して、見つかった問題を自動的に修正します。エージェントモードを使って、サイトに新機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる種類の作業に使います。エージェントモードは IDE 内で動作し、すばやくやり取りしながら進められます。Cloud agent はチームの一員のように非同期で作業し、issue とプルリクエストを通じてやり取りします。

この演習では、次のことを学びます。

- Copilot エージェントモードがプロジェクトを調べ、関連ファイルを特定し、複数のファイルにわたる変更を調整する方法
- GitHub Copilot エージェントモードを使って UI とデータレイヤー全体に機能を実装する方法
- コードベースにマージする前に、Copilot エージェントモードが作成した変更とテストをレビューする方法

## シナリオ

ゲームの一覧が増えてきたため、ユーザーがカテゴリやパブリッシャーで絞り込めるようにします。前の演習ではパブリッシャー ヘルパーを追加しました。次は、Copilot エージェントモードで残りのデータレイヤー、UI、テストの作業を完了します。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握しましょう。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディング プラットフォームです。ゲームの一覧と詳細を表示できます。単一の Astro アプリで、ビルド時にページを静的 HTML としてレンダリングします。ページは frontmatter から Drizzle ORM を通じてローカルの SQLite データベースを直接クエリします。別のバックエンド API やクライアント側 UI フレームワークはありません。再利用可能なデータ アクセス ヘルパーは `src/lib/` にあり、インタラクティブな機能は標準の DOM API を使った小さな Astro `<script>` で追加します。

### Web サイトを起動する

`npm run dev` タスクを実行すると、単一の Astro 開発サーバーが起動します。GitHub Codespace で次の手順を実行してください。

1. Codespace に戻ります。前の演習の後で `main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、Codespace で新しいターミナルを開きます。
3. フィルタリング作業用の新しいブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL が表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` をブラウザーで開くかどうかを尋ねるダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を選択する際、<kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押したままにします。

> [!NOTE]
> Codespace のターミナルで localhost URL を選択すると、`https://<your-codespace-name>-4321.app.github.dev/` に自動的に転送されます。これは Web サーバーをホストしている Codespace へのプライベート トンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームの一覧と、タイトル、画像、説明を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、そのタイトル、説明、パブリッシャー、カテゴリなどを確認できます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 次の演習を始める前に Codespace に戻り、Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を始めます。モードとモデルの選択は演習によって異なります。必要な場合は各手順で説明します。

Web サイトの初期実装は動作しますが、新しい機能を追加したいと考えています。まずバックログを確認しましょう。テンプレートからプロジェクトを作成すると、GitHub issue のバックログも自動的に作成されています。GitHub Copilot に、バックログの項目を表示するよう依頼します。

1. Chat ビューのエージェント ドロップダウンから **Agent** を選択します。**Agent** は複数のファイルにわたる変更を自律的に計画・実装し、ターミナル コマンドを実行して、ツールを呼び出します。

   ![Chat ビューのエージェント選択を示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデル一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> ワークショップの作成者が特定のモデルを推奨しているわけではありません。ワークショップを作成した際に Claude Sonnet 4.5 を使ったため、手順にも記載しています。提案の一貫性を高め、受講者がスムーズに進められることを期待しています。ただし LLM は確率的に動作するため、ここで示す内容と異なる提案が生成される場合があります。これは正常な動作です。

> [!NOTE]
> 確率的な性質により、Copilot が別の MCP コマンドを使うことがありますが、タスクは完了できるはずです。

3. 次のプロンプトを Copilot に送信して、issue のバックログを表示するよう依頼します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーに最も役立つ項目を基準に優先順位を付けるのを手伝ってください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot がユーザーに最も役立つと考える項目を基準に、優先順位も付けたことを確認できます。

## 命令ファイルを確認する

エージェントにコードを生成してもらう前に、Copilot に作業のコンテキストを与える命令ファイルを確認します。Web サイトに機能を追加する方法を説明する[ユーザー インターフェイス (UI) の命令ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能を追加する際の全般的なガイダンスを確認します。次の内容が含まれています。
   - アーキテクチャの概要
   - コンポーネントの設計、テスト容易性、アクセシビリティの原則
   - Astro、Tailwind CSS、Drizzle などのファイル種別に応じた命令ファイルへのリンク

> [!TIP]
> 命令ファイルから、ほかの命令ファイルとプロジェクト内のファイルを参照できます。パスは命令ファイルの場所からの相対パスです。命令の再利用、複雑な内容の分割、例やテンプレートの提示に役立ちます。

## フィルタリング機能を実装する

フィルタリングを完成させるには、少なくとも次の 3 か所を更新する必要があります。

- データレイヤー (`src/lib/`) にフィルタリングのロジックを追加または調整します。
- フィルタリングの動作を確認するテストを追加または更新します。
- ゲーム一覧ページにフィルタリング UI を追加します。

さらに、コードベースにマージする前にテストを実行し、すべて成功することを確認する必要があります。Copilot エージェントモードにこれらの作業を依頼しましょう。

1. 現在の Copilot の会話を続けるか、**New Chat** を選択して新しい会話を始めます。
2. **Add Context**、**Instructions**、**ui** の順に選択して、命令ファイルを追加します。

   ![UI 命令ファイルを選択する例を示すスクリーンショット](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント ドロップダウンで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択を示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

4. モデルが **Claude Sonnet 4.5** のままであることを確認します。
5. バックログの関連 issue に基づいて機能を実装するよう、次のプロンプトを使って Copilot に依頼します。

   ```plaintext
   バックログの関連する GitHub issue の要件に基づいて、サイトにパブリッシャーとカテゴリによるフィルタリングを追加してください。前の演習ですでにパブリッシャー ヘルパーを作成しているため、必要に応じてその作業を維持・改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、目的の機能に関連するファイルを探す様子を確認します。データレイヤーのヘルパー、UI、テストを見つけてファイルを変更し、テストを実行します。

   ![Copilot がプロジェクトのファイルを調べているスクリーンショット](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトを調べ、ファイルを変更し、テストを実行します。タスクやコードベースの複雑さによっては、数分かかることがあります。作業中、コード エディターに **Keep** と **Undo** のボタンが表示される場合があります。Copilot が完了すると、すべての変更に **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot に確認されたら **Continue** を選択してテストを実行します。

   ![Copilot Chat ペインでテストの実行許可を求めるダイアログのスクリーンショット](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot は、エラーがないと判断するまでコードの生成とテストを繰り返します。

   ![Copilot エージェントモードの完了した Chat セッションを示すスクリーンショット](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot やほかの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを表示しているブラウザーに戻り、新しい機能を確認します。
11. すべてが動作することを確認してコードのレビューを終えたら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

この演習では、GitHub Copilot エージェントモードを使って Tailspin Toys の Web サイトに機能を追加しました。次の方法を学びました。

- GitHub Copilot エージェントモードで UI とデータレイヤー全体に機能を実装する
- Copilot エージェントモードでプロジェクトを調べ、関連ファイルを特定し、複数ファイルの変更を調整する
- コードベースにマージする前に、Copilot エージェントモードが生成した変更とテストをレビューする

次は [Playwright MCP サーバーで機能をテストし][next-lesson]、プルリクエストを作成します。

### おまけの演習: ページネーションを実装する

ゲーム一覧が増えると、ページネーションが必要になります。この演習で学んだことを使い、Copilot にサイトへのページネーション実装を依頼します。次の点を検討してください。

- 既存の命令ファイルを使うなど、既存のベストプラクティスに従います。
- ユーザーにページサイズを選ばせるか、固定値にするかなど、ページネーションの方法を検討します。
- 希望する実装に必要なガイダンスをプロンプトに含めます。
- Copilot に変更を依頼し、コンテキストを追加しながら反復する場合があります。これは Copilot と作業する通常の進め方です。
