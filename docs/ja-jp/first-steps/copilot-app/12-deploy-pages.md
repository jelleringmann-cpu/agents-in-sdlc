GitHub Pages でデプロイして、Space Quiz を誰でも利用できるようにしましょう。Copilot はワークフローの準備とデプロイの案内を行えますが、変更をレビューし、サイトが公開されたことを確認するのはあなたの役目です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages デプロイの設定を依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの手順に従い、公開されたサイトを確認します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、まだ手軽に試せる場所がありません。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに、公開 URL から利用できるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードがコミットおよびプッシュされることがあります。プロンプトを送る前に、承認設定と送信先リポジトリを確認してください。**Approve all** を選択している場合、個別の確認プロンプトが表示されないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を使ってデプロイする準備をしてください。必要であればサイトをビルドし、変更がデフォルト ブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと必要な Pages の設定や権限を報告してください。マージ、自動マージの有効化、Pages の設定変更、デプロイは行わないでください。私のレビューを待ってください。
```

## ワークフローとプルリクエストをレビューする

1. README は、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プルリクエストの変更をレビューします。
3. ワークフローが、マージされていないプルリクエストではなくデフォルト ブランチからデプロイすることを確認します。
4. 修正が必要な場合は依頼し、更新された差分をレビューします。マージを許可する前に、必要なプルリクエストのチェックがすべて成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送ると、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、これらの操作に別の確認プロンプトが表示されない場合があります。

`<PR_NUMBER>` をレビューしたプルリクエストの番号に置き換え、この別のプロンプトを送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使って GitHub Pages を有効にし、必要なチェックが成功した後に限り、このプルリクエストだけをマージしてください。デプロイが成功するまで監視し、公開されたサイトの最終 URL を報告してください。Pages の有効化またはマージに必要な権限がない場合は、私が何を承認または実行する必要があるかを正確に伝えてください。サイトが公開されるまでは成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを行えない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは完了とみなさないでください。
