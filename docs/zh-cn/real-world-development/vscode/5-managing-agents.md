使用 GitHub Copilot 智能体模式时，它会自主探索代码库、提出更改建议、编辑文件并运行命令。由于这些工作在你的计算机上实时进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以直接在聊天中审查每个差异、接受或拒绝单项更改，并通过后续提示词引导对话、调整或扩展工作，全程无需离开编辑器。

本练习将介绍如何：

- 实时监控无障碍智能体的工作。
- 审查并接受它建议的文件编辑。
- 在会话进行中引导智能体，在高对比度模式之外添加浅色模式开关。

## 场景

[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出了一项需求：他们也希望为觉得默认主题太暗的用户添加浅色模式开关。你将引导现有会话扩展工作，而不是从头开始新对话。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。文件编辑会与差异以及 **Keep**/**Undo** 控件一起显示在聊天中。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天以查看每次工具调用。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 智能体提出文件编辑时，聊天中会显示差异：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你信任的命令。

5. 等待智能体完成高对比度模式实现。完成时会显示总结所做更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式已实现，现在在同一对话中继续添加浅色模式开关。智能体会保留先前工作的上下文，包括修改的组件、采用的样式方案和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示词：

    ```plaintext
    做得不错！现在请在高对比度开关旁添加浅色模式开关。浅色模式应采用相同方案，通过 local storage 持久保存，并且能在 UI 的同一区域中访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会继续工作，检查已有更改并提出浅色模式的实现。
3. 像审查高对比度模式一样，逐项检查新的编辑，并在每个差异中选择 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期（例如尝试重构你不想改动的开关 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送补充说明。

> [!TIP]
> 在进行中的会话里提供指导，比从头开始更快。可以用后续提示词调整实现（例如“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（例如“不要添加第三个开关，请将浅色模式整合到现有设置面板”），或扩展范围（例如“为两个开关都添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查完整的已更改文件列表。应该能看到 Astro 组件、样式和相关测试的更新。
3. 打开其中几个文件，查看差异。确认自定义智能体的无障碍模式已体现出来，包括 ARIA 属性、键盘导航、语义化 HTML，以及通过本地存储持久保存设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结与后续步骤

你使用 Copilot Chat 智能体模式监控并引导了一个进行中的会话：检查每项文件编辑、接受或拒绝更改，并在保留上下文的情况下发送后续提示词来扩展工作。

本课中，你探索了：

- 实时监控智能体工作。
- 接受或拒绝单项文件编辑。
- 在会话进行中使用后续提示词引导智能体。

在[下一课][next-lesson]中，你将发布无障碍功能，并审查本实验中本地自定义智能体生成的更改。
